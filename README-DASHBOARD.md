# منيو O2 الإلكتروني — مربوط بلوحة تحكم البوت

نفس التصميم والصفحات والمكوّنات كما هي. الفرق الوحيد: **التوفّر يأتي حيّاً من اللوحة**، فما يُغلقه الكاشير يختفي من الموقع خلال دقيقة.

---

## التشغيل في ثلاث خطوات

### ١. متغيّرات البيئة

انسخ `.env.local.example` إلى `.env.local` (محلياً)، أو ضع القيم في متغيّرات بيئة المنصة (عند النشر):

```
BOT_ORIGIN=https://o2bot.onrender.com
NEXT_PUBLIC_USE_BOT_PROXY=1
NEXT_PUBLIC_IMAGE_BASE=https://o2bot.onrender.com
```

### ٢. البناء والتشغيل

```bash
npm install
npm run build
npm start
```

### ٣. التحقق

افتح `/live-debug` — تفحص أربعة مستويات وتقول أين الخلل إن وُجد.

## ما تغيّر بالضبط

| الملف | التغيير |
|---|---|
| `lib/live-menu.ts` | **جديد** — يجلب التوفّر من البوت ويدمجه مع المنيو الثابت |
| `lib/img.ts` | **جديد** — مصدر موحّد لصور المنيو |
| `app/live-debug/page.tsx` | **جديد** — صفحة تشخيص |
| `server.js` | **جديد** — خادم يستمع على `0.0.0.0` والمنفذ من المنصة |
| `next.config.mjs` | وسيط `/bot-api/*` و`/menu/*`، وإطفاء مُحسِّن الصور |
| `lib/menu-data.ts` | **لم يتغيّر** — الأسماء والأوصاف والأحجام كما هي |
| 4 صفحات + `product-card` | `getMenuByBranch` ← `useLiveMenu`، و`item.image` ← `imgSrc(item.image)` |

**التصميم لم يُمس.** لا تغيير في التنسيقات ولا التخطيط ولا الحركات.

## كيف يعمل

```
lib/menu-data.ts   (ثابت: الأسماء، الأوصاف، الأحجام، مسارات الصور)
        +
البوت /api/public/menu   (حيّ: active + السعر المفرد)
        =
useLiveMenu(branch)  →  منيو جاهز للعرض
```

المطابقة بالقسم والاسم مع تطبيع عربي، فـ«فرشوحه» تطابق «فرشوحة». والأسماء المكررة داخل القسم تُطابَق بالترتيب.

**إن غاب البوت — نائم أو معطّل أو لا إنترنت — يعمل الموقع بالمنيو الثابت كما كان تماماً.** لا شاشة بيضاء ولا منيو فارغ. وإن نجح الجلب مرة ثم فشل، تبقى آخر نسخة معروضة.

التحديث: عند فتح الصفحة · كل 45 ثانية · عند العودة للتبويب.

## اختبار الربط

1. اللوحة ← المنيو ← أغلق «باشكا»
2. انتظر دقيقة
3. حدّث صفحة الشاورما في الموقع ← يختفي
4. أعد تفعيله ← يظهر
